# CLAUDE.md — Alexela 2024 Annual Report

Project: static multi-page HTML site for Alexela's 2024 annual report. Bilingual (Estonian root + English mirror in `en/`). No framework. Build is PostCSS only.

## Always load these skills

- **`project-conventions`** — CSS class taxonomy (section types, block types), file layout, PostCSS pipeline, JS conventions. Loads automatically when editing HTML/CSS/JS in this repo.
- **`et-en-parity`** — bilingual page mapping and what must be mirrored vs differ. Triggers whenever a root `*.html` or `en/*.html` is edited.

## CSS workflow

- Edit only `src/style.css` and `src/partials/*.css`.
- **Never edit `css/style.css` by hand** — it's compiled output.
- A PostToolUse hook in `.claude/settings.json` runs `npm run css:build` automatically after any `src/**/*.css` edit, so you do not need to invoke the build manually.

## Dev server

- `npm run dev` — starts PostCSS watch + BrowserSync at http://localhost:3000. HTML / JS changes do a full page reload; CSS changes inject without reload.
- `npm run serve` — BrowserSync only (no PostCSS watch), if you only want to view the current build.
- BrowserSync config lives in `bs-config.cjs`. The previous VS Code Live Server (port 5502) still works but doesn't watch the PostCSS rebuild — prefer `npm run dev`.

## Production build

- `npm run build` — runs `scripts/build.sh`: cleans `dist/`, rebuilds minified CSS, then rsyncs only the files a static host needs (HTML, `css/`, `main.js`, `img/`, `video/`, `fonts/`, favicons, `*.pdf`) into `dist/`. Excludes `src/`, tooling configs, `.claude/`, `.github/`, `.vscode/`, `scripts/`, `test_accordion.html`, and any `raw-material-*` working folders.
- `dist/` is gitignored — it is regenerated by `npm run build` and by the GitHub Actions workflow on every push to `main`.
- The GitHub Pages workflow at `.github/workflows/static.yml` runs `npm ci && npm run build` and deploys `dist/` (not the whole repo, as it used to).
- If you add a new top-level folder that should ship, no change needed — the script copies everything by default. If you add a top-level folder that should NOT ship, add an `--exclude="/foldername/"` line in `scripts/build.sh`.

## When to use the `et-en-parity-reviewer` subagent

After non-trivial edits to a page pair, or when the user asks for a parity check. The agent is read-only and returns a structured punch list — use it to verify that mirroring was complete before saying done.

## Accessibility

The global `wcag-review` skill auto-runs after HTML edits. Don't bypass its findings — fix what it flags before marking work complete.

## House style

- Vanilla JS only. No bundler, no TypeScript, no framework. Extend `main.js`.
- BEM-ish class naming. See `project-conventions` skill.
- Estonian comments in the codebase are intentional (`postcss.config.js` is in Estonian) — leave them as-is.
- Don't reintroduce a `main copy.js` or other duplicate working files — clean up as you go.
